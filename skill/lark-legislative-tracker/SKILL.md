# Lark Legislative Tracker — Argentina

Process Argentine bills (proyectos de ley) and produce a ready-to-upload Excel file with one row
per bill, all columns in English, matching the Lark tracker format exactly.

## Input modes

### Mode A — Pre-structured rows from Smart Snippet (primary flow)

The user pastes tab-separated rows generated by the internal **Smart Snippet** app ("Copiar para
Claude" button in the Consolidado TikTok view). Each row already comes in the exact order of the
17 tracker columns, **plus an extra 18th column at the end with the URL to the bill's text**.
The paste usually includes its own instructions header — those instructions and this skill agree;
follow them.

Rules for Mode A (these override any judgment of your own):

- **NEVER change:** `Business Impact` (already rated by the team in the app — it is a human
  judgment, not yours to re-infer), `Project number`, `Legislator`, `Date of presentation`,
  `Update date`, `Status`.
- **Translate `Proposed changes` to English** — 2–4 sentences, neutral and factual. The input
  arrives in Spanish.
- **Replace `Bill (link)`** with the short thematic English title (see Title Naming Guide below).
  The input brings the literal Spanish title — do not keep it. Use the extra 18th column as the
  **hyperlink** of this cell in the Excel. Do NOT include the extra column as a column.
- **Fill `Likelihood of Approval`** (High / Normal / Low) using the guidelines below — it comes
  empty.
- **`Topic`:** if it already matches the fixed list below, keep it; if it comes in Spanish or
  empty, pick the right value from the list.
- **`Notes`** comes pre-built ("Submitted to Committees | Project presented by [bloc]") — keep it;
  complete it only if the bloc part is missing and you can infer it from `Legislator`.
- Dates already arrive as `YYYY-MM-DD` — keep them as-is.

### Mode B — Raw bills (legacy flow)

The user may instead provide bills as: text pasted in chat, an attached file (PDF, Word, Excel),
or a URL to the Argentine Congress website (hcdn.gob.ar or senado.gob.ar — use web_fetch to
retrieve content). In this mode, extract or infer every column yourself using the definitions
below.

## Column definitions (exact Lark order)

| Column | How to fill |
|---|---|
| Bill (link) | Short thematic English title (NOT the literal bill name) — see Title Naming Guide. Hyperlinked to the bill text when a URL is available |
| Update date | Mode A: keep as provided. Mode B: today's date |
| Proposed changes | 2–4 sentences in English, neutral and factual |
| Business Impact | Mode A: keep as provided. Mode B: High / Normal / Low per guidelines |
| Likelihood of Approval | High / Normal / Low per guidelines |
| Status | In progress / Expired / Complete |
| Notes | "Submitted to Committees \| Project presented by [bloc/party]" |
| Legal Analysis/ ALAI comments | Leave blank unless the user provides content |
| Internal Contacts | Leave blank unless the user specifies |
| Date of presentation | Date the bill was formally introduced |
| National/provincial | National, City of Buenos Aires, Buenos Aires Province, or the province name |
| Home Chamber | Deputies, Senate, or Provincial Deputies / Provincial Senators |
| Project number | Exactly as written (e.g. 1234-D-2025, 567-S-2025) |
| Legislator | Full name(s) with party in parentheses; multiple: "Name (Party); Name (Party)" |
| Topic | From the fixed list below |
| Parent items | Leave blank |
| Field 1 | Leave blank |

## Topic — allowed values (fixed list)

Pick the single most appropriate topic. If a bill clearly spans two topics (e.g. Influencers +
Online Gambling), use both separated by `/`.

Digital Tax · Influencers regulation · Audiovisual / Digital platforms · Illegal Content /
Content moderation · Access to Information · Child Abuse / Child Safety · Cyberbullying ·
Digital Care / Digital Environments · Digital Violence (women) · Social Media · Online gambling ·
AI · AI in education · AI electoral framework · Data protection / Personal Data ·
Cyberprotection / Digital security · Use of cell phones · Consumer protection · Biometric Data ·
Grooming · Education / Digital Education · Training program

## Bill (link) — Title Naming Guide

The `Bill (link)` field reflects the **thematic axis** — what the bill is fundamentally about —
not the literal title. Use short, descriptive English titles like those already in the tracker:

| Literal bill name | Bill (link) title to use |
|---|---|
| "Proyecto que modifica art. 128 del Código Penal respecto a IA" | Artificial Intelligence |
| "Régimen de regulación de juegos de azar en línea" | Regulation of online gambling |
| "Proyecto sobre violencia digital contra la mujer" | Protection against violence towards women in digital environments |
| "Ley de protección de datos personales de niños" | Child Digital Protection |
| "Campaña de concientización sobre ciberbullying" | National Bullying and Cyberbullying Prevention Strategy |

When in doubt, follow the naming pattern of similar bills already in the tracker.

## Business Impact & Likelihood of Approval — guidelines

**Business Impact** (Mode B only — in Mode A it comes rated by the team and must not change):
- **High** — directly affects core operations, creates new compliance obligations, or imposes
  significant costs/taxes
- **Normal** — relevant but manageable; creates reporting or registration obligations
- **Low** — awareness campaigns, education programs, minor modifications

**Likelihood of Approval:**
- **High** — advanced in the legislative process, broad cross-party support, or sent by the
  Executive
- **Normal** — standard committee process, moderate support
- **Low** — early stage, expired in prior session, niche topic, or opposition-only support

## Status guidelines

- **In progress** — currently in committee or active in the current session
- **Expired** — presented in a prior legislative session (bills expire after 2 years if not
  approved). Likely Expired if the project number year is 2 or more years old with no sign of
  approval
- **Complete** — approved by both chambers and enacted into law

In Mode A, Status comes as "In progress" — keep it unless the project number clearly indicates an
expired session.

## Workflow

1. Detect the mode: tab-separated 17+1-column rows → Mode A; anything else → Mode B.
2. Mode B only: fetch URLs / read attachments, then extract all column values per bill.
3. Process ALL bills first, then generate the Excel in one step.
4. Generate the Excel with openpyxl and present it.

## Excel generation

Use openpyxl. Column order must match exactly:

```python
columns = [
    'Bill (link)', 'Update date', 'Proposed changes', 'Business Impact',
    'Likelihood of Approval', 'Status', 'Notes', 'Legal Analysis/ ALAI comments',
    'Internal Contacts', 'Date of presentation', 'National/provincial',
    'Home Chamber', 'Project number', 'Legislator', 'Topic', 'Parent items', 'Field 1'
]
```

- Dates as `YYYY-MM-DD`.
- Column widths: Bill (link) = 35, Proposed changes = 60, all others = 20. Bold header row.
- Mode A: set the `Bill (link)` cell hyperlink to the URL from the extra 18th input column
  (`cell.hyperlink = url`, style the cell as a link). Do not add the URL as a column.
- Save to `/mnt/user-data/outputs/new_PLs_YYYY-MM-DD.xlsx` (today's date).

## Output

Present the file, then a brief inline summary — one line per bill:
`bill title | topic | business impact | status`.
If any value was inferred with low confidence (Likelihood, Topic, Expired), flag it in one short
line so the user can double-check before uploading.
